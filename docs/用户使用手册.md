# WireClaw 使用说明

这是一份面向使用者的说明，只讲怎么用，不展开代码实现。

适用场景：
- 首次烧录后不会配网
- 不知道 `config.json` 怎么填
- 想接入自己的 QQ 机器人
- 想知道配网页面每一项怎么输入

---

## 1. 整体使用流程

可以按下面这张流程表来理解：

| 步骤 | 你要做什么 | 结果 |
|---|---|---|
| 1 | 烧录固件到 ESP32 | 设备启动 |
| 2 | 设备进入配网模式 | 出现 `WireClaw-Setup` 热点 |
| 3 | 手机连接热点并打开配网页面 | 填写 WiFi、模型、QQBot 信息 |
| 4 | 保存配置并重启 | 设备连上你的路由器 |
| 5 | 用浏览器打开设备配置页 | 继续修改配置 |
| 6 | 用 QQ 给机器人发消息 | 开始正常使用 |

---

## 2. 首次上电怎么配网

### 2.1 什么时候会进入配网模式

设备在下面两种情况下会进入配网模式：

- 没有 WiFi 配置
- 有 WiFi 配置，但连接失败

进入后会启动一个热点：

- 热点名称：`WireClaw-Setup`

### 2.2 手机上怎么操作

1. 打开手机 WiFi
2. 找到 `WireClaw-Setup`
3. 连接这个热点
4. 打开浏览器访问：
   - `http://192.168.4.1`
5. 在页面中填写配置
6. 点击保存
7. 设备会自动重启并连接你填写的 WiFi

如果手机没有自动弹出配网页面，直接手动输入 `192.168.4.1` 即可。

## 3. 配网页面每一项怎么填

下面这张表按“页面字段名 / 填什么 / 示例 / 是否必须”整理。

### 3.1 基础网络与模型配置

| 页面字段 | 填什么 | 示例 | 是否必须 |
|---|---|---|---|
| `WiFi SSID` | 你的路由器 WiFi 名称 | `Xiaomi_2.4G` | 是 |
| `WiFi Password` | 你的 WiFi 密码 | `12345678` | 是 |
| `API Key` | 你的大模型平台密钥 | `sk-xxxx` | 是，除非你接本地模型 |
| `Model` | 要使用的模型名 | `MiniMax-M2.5` | 是 |
| `Device Name` | 给设备起个名字 | `wireclaw-01` | 建议填 |
| `API Base URL` | 大模型接口完整地址 | `https://api.minimaxi.com/v1/chat/completions` | 是，如果不是默认平台 |
| `NATS Host` | NATS 服务器地址 | `192.168.1.20` | 否 |
| `NATS Port` | NATS 端口 | `4222` | 否 |
| `Timezone` | 时区字符串 | `UTC0` | 建议填 |

### 3.2 消息平台配置

当前页面支持选择：

- `Telegram`
- `QQ`

如果你只打算用 QQ，就选 `QQ`，并填写 QQ 相关字段。

### 3.3 QQ 配置项怎么填

| 页面字段 | 填什么 | 示例 | 是否必须 |
|---|---|---|---|
| `Message Platform` | 选择消息平台 | `QQ` | 是 |
| `QQ App ID` | 你的 QQBot AppID | `190xxxxxxx` | 是 |
| `QQ App Secret` | 你的 QQBot Secret | `abcd1234xxxx` | 是 |
| `QQ Cooldown (seconds)` | QQ 消息冷却时间，单位秒 | `15` | 建议填 |

说明：

- `QQ App ID` 和 `QQ App Secret` 必须是你自己创建的 QQBot 对应的值
- `QQ Cooldown` 表示规则触发消息时的最小发送间隔
- 一般填 `15` 就够用

### 3.4 如何判断自己填对了

保存并重启后，看串口日志是否类似：

| 日志 | 说明 |
|---|---|
| `QQ: enabled (AppID: ...)` | QQ 已启用 |
| `[QQ] Access token obtained` | 成功拿到 token |
| `[QQ] Gateway: ...` | 成功拿到网关地址 |
| `[QQ] READY session=...` | QQ WebSocket 已连接成功 |

如果没有这些日志，说明 QQ 配置还没成功。

## 4. `config.json` 该怎么填

如果你不想通过配网页面输入，也可以直接编辑 `data/config.json`。

推荐最小可用示例：

```json
{
  "wifi_ssid": "你的WiFi名称",
  "wifi_pass": "你的WiFi密码",
  "api_key": "你的模型平台Key",
  "model": "MiniMax-M2.5",
  "device_name": "wireclaw-01",
  "api_base_url": "https://api.minimaxi.com/v1/chat/completions",
  "nats_host": "",
  "nats_port": "4222",
  "message_platform": "qq",
  "telegram_token": "",
  "telegram_chat_id": "",
  "telegram_cooldown": "15",
  "qq_app_id": "你的QQ AppID",
  "qq_app_secret": "你的QQ AppSecret",
  "qq_cooldown": "15",
  "timezone": "UTC0"
}
```

建议：

- 如果你只用 QQ，就把 Telegram 相关字段留空
- 如果你不用 NATS，就把 `nats_host` 留空

## 5. 如何创建自己的 QQBot

你给的官方入口是：

- https://q.qq.com/qqbot/openclaw/

按当前官方入口，建议你从这个页面进入 QQ 机器人开放平台，然后完成机器人创建和资料获取。

可以按下面的顺序操作：

| 步骤 | 操作 |
|---|---|
| 1 | 打开官方入口页面 |
| 2 | 登录你的 QQ / 平台账号 |
| 3 | 进入机器人或应用创建入口 |
| 4 | 创建一个新的 QQBot |
| 5 | 按页面要求填写机器人名称、简介、头像等信息 |
| 6 | 开通消息能力或对应权限 |
| 7 | 在控制台中找到 `AppID` 和 `AppSecret` |
| 8 | 把这两个值填到 WireClaw 的配网页面或 `config.json` 中 |

你最终真正要拿到的就是两项：

| 参数 | 用途 |
|---|---|
| `AppID` | 填到 `QQ App ID` |
| `AppSecret` | 填到 `QQ App Secret` |

### 5.1 创建完成后还要做什么

创建 QQBot 后，通常还需要检查这些内容：

| 检查项 | 说明 |
|---|---|
| 机器人是否已发布或可测试 | 否则可能无法正常对话 |
| 是否开通消息事件 | 否则收不到消息 |
| 是否允许私聊 / C2C 消息 | 否则无法通过私聊测试 |
| 是否已经把机器人加到目标环境 | 否则你发消息它收不到 |

### 5.2 推荐测试方法

建议先用最简单的方式验证：

1. 先完成 AppID / AppSecret 配置
2. 确认设备日志里出现 `READY`
3. 再从 QQ 给机器人发一条简单消息，比如：
   - `你好`
   - `讲个故事`

如果日志里出现类似：

```text
[QQ] C2C_MESSAGE_CREATE: 你好
```

说明入站消息已经通了。

## 6. 怎么选择模型平台

这个工程现在最常见的几种配置方式如下。

### 6.1 MiniMax

| 项 | 填写内容 |
|---|---|
| `API Key` | 你的 MiniMax Key |
| `Model` | `MiniMax-M2.5` |
| `API Base URL` | `https://api.minimaxi.com/v1/chat/completions` |

### 6.2 Swoole

| 项 | 填写内容 |
|---|---|
| `API Key` | 你的 Swoole Key |
| `Model` | 建议使用平台明确支持的模型名 |
| `API Base URL` | `https://chat.swoole.com/v1/chat/completions` |

### 6.3 本地 Ollama

| 项 | 填写内容 |
|---|---|
| `API Key` | 可留空 |
| `Model` | 例如 `gpt-oss:latest` |
| `API Base URL` | 例如 `http://192.168.1.50:11434/v1/chat/completions` |

## 7. 设备联网后怎么继续配置

设备连接到你的 WiFi 后，可以直接在浏览器里打开配置页继续修改。

访问方式：

- `http://设备IP/`
- `http://设备名.local/`

例如：

- `http://192.168.1.88/`
- `http://wireclaw-01.local/`

你可以在这里继续修改：

| 页面区域 | 用途 |
|---|---|
| `Config` | 修改 WiFi、模型、QQ、NATS 等配置 |
| `Prompt` | 修改系统提示词 |
| `Memory` | 修改记忆内容 |
| `Status` | 看设备当前状态 |

## 8. 如何确认设备已经正常工作

你可以按这张检查表来确认：

| 检查项 | 正常表现 |
|---|---|
| 配网成功 | 设备不再进入 `WireClaw-Setup` |
| WiFi 成功 | 串口能看到本地 IP |
| Web 配置页可访问 | 浏览器能打开设备配置页 |
| QQ 启用成功 | 串口出现 `QQ: enabled` |
| QQ 网关成功 | 串口出现 `READY` |
| 消息能收 | 发消息后串口出现 `C2C_MESSAGE_CREATE` |
| 消息能回 | 机器人能回复你 |

## 9. 常见问题

### 9.1 手机搜不到 `WireClaw-Setup`

先检查：

| 检查项 | 说明 |
|---|---|
| 设备是否真的进入配网模式 | 看串口 |
| 供电是否稳定 | 供电不稳会反复重启 |
| 是否是 2.4G 设备 | 手机会在 2.4G 下看到这个热点 |
| 设备是否启动后马上崩溃 | 热点会一闪而过 |

### 9.2 连上热点但页面打不开

尝试：

1. 手动访问 `192.168.4.1`
2. 不要等系统自动弹窗
3. 关闭手机的“自动切回有网 WiFi”功能

### 9.3 QQ 已启用但机器人不回消息

优先检查：

| 检查项 | 说明 |
|---|---|
| `AppID` / `AppSecret` 是否填对 | 最常见问题 |
| 是否拿到 token | 日志里应有 `Access token obtained` |
| 是否拿到 gateway | 日志里应有 `Gateway` |
| 是否收到 `READY` | 没有 READY 就还没连通 |
| 是否真的收到了你的消息 | 看是否有 `C2C_MESSAGE_CREATE` |

### 9.4 模型有回复，但硬件没动作

这类问题一般要区分两种情况：

| 情况 | 含义 |
|---|---|
| 模型只说“已经完成” | 可能没有真的调用工具 |
| 串口显示工具已调用但硬件没反应 | 再查硬件或引脚 |

## 10. 推荐的最小使用方案

如果你只是想尽快跑起来，最推荐的组合是：

| 项目 | 推荐值 |
|---|---|
| 芯片 | ESP32-C6 |
| 模型平台 | MiniMax |
| 模型 | `MiniMax-M2.5` |
| 消息平台 | QQ |
| QQ 配置 | 你自己的 `AppID` + `AppSecret` |

最小步骤就是：

1. 烧录
2. 连 `WireClaw-Setup`
3. 打开 `192.168.4.1`
4. 填 WiFi
5. 填 MiniMax Key / URL / Model
6. 选择 `QQ`
7. 填 `QQ App ID` 和 `QQ App Secret`
8. 保存重启
9. 看日志出现 `READY`
10. 用 QQ 发消息测试

---

## 11. 你真正要准备的东西

最后用一张总表收口。

| 类型 | 你需要准备什么 |
|---|---|
| 硬件 | 一块 ESP32 板子 |
| 网络 | 2.4G WiFi |
| 模型 | 一个可用的 API Key |
| 模型接口 | 一个正确的 `API Base URL` |
| QQBot | 自己创建的 `AppID` 和 `AppSecret` |
| 浏览器 | 用来访问 `192.168.4.1` 和设备配置页 |

只要这些都准备好，就可以完成整套流程。
